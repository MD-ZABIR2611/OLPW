Programming & Computational Thinking

Computational thinking turns real problems into step-by-step solutions. Pseudocode, flowcharts and trace tables let you design and test an algorithm before writing a single line of code.

Key Concepts

01

Computational thinking breaks problem-solving into four skills: decomposition, pattern recognition, abstraction and algorithm design.

02

An algorithm is a precise step-by-step method built from sequence (steps in order), selection (IF...THEN...ELSE) and iteration (FOR, WHILE and REPEAT...UNTIL loops).

03

Pseudocode writes the algorithm in structured plain language, so its logic can be planned and checked before it is coded in a real programming language.

04

A flowchart represents the algorithm with standard symbols: a rounded rectangle (terminator) for start and end, a rectangle for a process, a diamond for a decision and a parallelogram for input or output.

05

A trace table dry-runs an algorithm by recording the value of every variable each time it changes, exposing logic errors in loops and selections before coding begins.

06

In exam trace-table questions most marks are for the intermediate values, so complete every row and read the loop condition carefully to decide whether the test happens before or after each pass.

02

Key Terms

TermExam definition
Computational thinkingThe thought process of formulating problems and their solutions so they can be carried out by a computer, using decomposition and abstraction.
DecompositionBreaking a complex problem down into smaller, simpler parts that can be solved one at a time and then combined.
AbstractionRemoving unnecessary detail from a problem so that only the information essential to solving it is kept.
AlgorithmA precise, step-by-step set of instructions that solves a problem or completes a task in a finite number of steps.
PseudocodeA structured, plain-language description of an algorithm using keywords, which can be understood without knowing a real programming language.
FlowchartA diagram that represents an algorithm using standard symbols connected by arrows to show the order of operations.
Trace tableA table used to dry-run an algorithm by recording the changing values of its variables at each step to check that it works correctly.
IterationThe repeated execution of a block of instructions in an algorithm, achieved with loops such as FOR, WHILE or REPEAT...UNTIL.
03

Exam Tip

Exam tip

In trace-table questions draw the table with one column per variable and complete every row before writing the final output; most marks are for intermediate values, and one wrong early row usually costs the rest.

04

Practice Questions

Structured practice — write your answer, then reveal the model.

FOUNDATION

Name the standard flowchart symbol used for each of the following, and state what it represents: (a) a decision, (b) a process, (c) the start or end of the chart, (d) an input or output of data.

Model answerDiamond: a decision with yes/no branches (1). Rectangle: a process or action (1). Rounded rectangle or oval (terminator): the start or end of the flowchart (1). Parallelogram: an input or output of data (1).
CHALLENGE

A student plans an algorithm in pseudocode and tests it with a trace table before coding it in JavaScript. Explain the advantages of each tool and why testing the logic first saves time.

Model answerPseudocode uses structured plain language, so the logic can be planned and read without learning a programming language's syntax (1); it is quick to write and easy to change while the design is still being decided (1). A trace table dry-runs the algorithm, recording each variable every time it changes, so errors in loops and selections are found on paper (1). Fixing logic errors before coding avoids rewriting and debugging large amounts of code later (1). Therefore the marks in trace-table questions reward completing every row accurately, not just the final answer (1).
